# SaleScout mini

Мини-версия прайс-бота: чистая функция расчёта, Express API и страница React/Vite с таблицей «было / стало». Проект работает локально и не отправляет изменения в Kaspi.kz.

## Быстрый запуск

Нужны **Node.js 20** и npm. Версия Node указана в `.nvmrc`. Все команды выполняются из корня **этого** проекта — папки `новое_тз`, где находятся `package.json` и `src/pricing.ts`.

```sh
npm install
npm run dev
```

Откройте **http://127.0.0.1:5173**. API слушает **http://127.0.0.1:3001**. Команда `npm run dev` запускает оба процесса; `Ctrl+C` останавливает их.

При открытии страница отправляет демонстрационные товары в `POST /reprice`. Кнопка «Пересчитать цены» повторяет запрос. Доступны поиск, фильтр по причине и раскрывающийся JSON-редактор для своих товаров. Ошибки ввода и сети отображаются на странице; при неудачном повторном запросе предыдущие результаты сохраняются с предупреждением.

Если нужно запустить процессы отдельно, используйте два терминала:

```sh
npm run dev:server
```

```sh
npm run dev:client
```

Vite перенаправляет `/reprice` на Express, поэтому дополнительная настройка CORS не нужна. По умолчанию используются порты 5173 и 3001. Если меняете переменную `PORT`, задайте одинаковое значение для обоих процессов. Например, в PowerShell перед `npm run dev`: `$env:PORT = '3002'`.

## Проверка и production-сборка

```sh
npm test
npm run typecheck
npm run build
npm start
```

После сборки **http://127.0.0.1:3001** обслуживает и React-страницу, и API одним процессом. Перед `npm start` остановите dev-сервер, если он занимает тот же порт. Сборка находится в `dist/`, зависимости и результаты сборки не включены в Git.

- `npm test` — однократный запуск всех тестов Vitest.
- `npm run test:watch` — тесты в режиме наблюдения.
- `npm run typecheck` — строгая проверка TypeScript без генерации файлов.
- `npm run build` — проверка типов, сборка Vite и компиляция сервера.
- `npm ci` — воспроизводимая установка по `package-lock.json` (используется в CI).

GitHub Actions запускает тесты и сборку на Node.js 20 при push и pull request.

## API

**`POST /reprice`**, заголовок `Content-Type: application/json`, тело — массив `Product[]`.

Пример для bash:

```sh
curl http://127.0.0.1:3001/reprice \
  -H 'Content-Type: application/json' \
  --data-binary @data/products.json
```

Для Windows PowerShell используйте именно `curl.exe`:

```powershell
curl.exe http://127.0.0.1:3001/reprice -H "Content-Type: application/json" --data-binary "@data/products.json"
```

Успешный ответ `200` — массив результатов в порядке входных товаров:

```json
[
  {
    "sku": "APL-15-128",
    "oldPrice": 399990,
    "newPrice": 384980,
    "reason": "UNDERCUT"
  }
]
```

Имя товара берётся на клиенте из отправленного массива по индексу: схема `PriceResult` не расширяется, одинаковые SKU не теряются. Пустой массив возвращает `[]`.

API возвращает `400` и `{ "error": "..." }` для тела, которое не является массивом, повреждённого JSON и некорректного товара. Проверяются типы всех полей, конечность и неотрицательность чисел, целочисленность границ, `minPrice <= maxPrice` и структура конкурентов. Товар целиком проверяется до расчёта; при ошибке в одном товаре отклоняется весь запрос. Размер тела ограничен 1 МБ; превышение возвращает `413`.

## Правила расчёта

Именованный экспорт `calculatePrice(product)` находится в **`src/pricing.ts`**. Функция не выполняет I/O, не валидирует и не меняет входной объект.

1. Один проход по конкурентам находит минимальную цену среди `inStock: true`.
2. Если таких конкурентов нет, возвращаются `maxPrice` и `NO_COMPETITORS`.
3. Иначе вычисляется `candidate = Math.floor(best - step)`.
4. Если кандидат строго ниже `minPrice`, результат — `minPrice` и `AT_MIN`; если строго выше `maxPrice` — `maxPrice` и `AT_MAX`.
5. В остальных случаях возвращаются кандидат и `UNDERCUT`. Равенство любой границе входит в эту ветку.

`myPrice` только копируется в `oldPrice`. Даже если текущая цена выходит за диапазон, она не меняет результат расчёта. При `step = 0` новая цена может совпадать с ценой конкурента. Вычисления используют стандартные числа JavaScript и `Math.floor` без дополнительных поправок на точность.

Сложность: **O(n)** по числу конкурентов и **O(1)** дополнительной памяти. Используется цикл без сортировки и без передачи большого массива аргументов в `Math.min`.

## Структура

```text
src/
  pricing.ts             Чистая функция calculatePrice
  types.ts               Типы из задания
server/
  app.ts                 Express-приложение без запуска порта при импорте
  validation.ts          Проверка данных API
  index.ts               Запуск сервера
client/
  src/App.tsx            Таблица, запросы, фильтры и JSON-редактор
  src/styles.css         Адаптивные стили
data/
  products.json          Демонстрационные входные данные
  expected.json          Ожидаемые результаты
tests/
  pricing.test.ts        Правила расчёта и граничные случаи
  api.test.ts            HTTP-контракт и валидация
  ui.test.tsx            Поведение React-страницы в jsdom
```

Исходных файлов-примеров в рабочей папке не было: `data/products.json` и `data/expected.json` созданы по пяти числовым примерам из задания. Это демонстрационные товары, а не данные с Kaspi.kz.

Тесты проверяют все причины, доступность конкурентов, совпадающие минимальные цены, дробные значения, нулевой шаг и цены, включённые границы, равные границы, независимость от `myPrice`, отсутствие мутаций и большой список конкурентов. API-тесты используют настоящий Express через Supertest. UI-тесты проверяют таблицу, запросы, поиск, фильтр, JSON, восстановление после ошибки и повторяющиеся SKU; HTTP-ответы в них подменяются. jsdom не проверяет визуальную раскладку в настоящем браузере.

## Публикация на GitHub

Папка содержит отдельный Git-репозиторий с коммитами по этапам. Для сдачи создайте пустой публичный репозиторий **salescout-mini** в своём аккаунте GitHub (без автоматически созданных README и `.gitignore`), затем из этой папки выполните:

```sh
git remote add origin https://github.com/YOUR_USERNAME/salescout-mini.git
git push -u origin main
```

Замените `YOUR_USERNAME` на свой логин. Ссылку на созданный репозиторий можно добавить в сопроводительное письмо на hh.kz. Не отправляйте ссылку на внешний проект `DataProject`: корень сдаваемого репозитория должен непосредственно содержать `src/pricing.ts`.

Разработка выполнена с помощью AI-инструмента. Перед интервью полезно самостоятельно разобрать расчёт, проверки API и поток данных React → Express → React; отдельные этапы видны в истории Git.
