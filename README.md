# SaleScout

Веб-приложение для расчёта конкурентных цен: регистрация, подтверждение почты, личный кабинет и отдельный каталог товаров каждого пользователя. React + TypeScript + Express + PostgreSQL.

Добавляйте товары через форму, задавайте цены конкурентов и получайте таблицу «было / стало» с причиной изменения. **Сервис рассчитывает рекомендации; подключение к Kaspi.kz и автоматическая отправка цен не реализованы.**

## Запустить после скачивания

Нужны **Node.js 20 или 24**, npm и запущенный **Docker с Compose v2**. Все команды выполняются в корне этого репозитория, где находится `package.json`. Production-образ использует Node.js 24; совместимость исходного задания с Node.js 20 проверяется в CI.

```sh
npm install
npm run setup
docker compose up -d --build
```

- Приложение: **http://localhost:3001**.
- Письма для локальной проверки: **http://localhost:8025** (Mailpit).
- `setup` создаёт `.env` со случайными паролем БД и секретом сессии. Существующий `.env` не перезаписывается.
- База сохраняется в Docker volume; перезапуск приложения не удаляет пользователей и товары.

Создайте аккаунт с любым корректным тестовым email. Откройте Mailpit, найдите письмо, перейдите по ссылке и подтвердите почту. После входа нажмите «Добавить товар», заполните форму и затем «Рассчитать цены». Локальные письма **не отправляются в интернет**.

Остановка без удаления базы:

```sh
docker compose down
```

Не добавляйте `-v`, если хотите сохранить данные. Команда с `-v` удаляет том базы.

## Что работает

- Регистрация, подтверждение почты, вход и выход.
- Вход через Google и Apple после настройки провайдеров; привязка из личного кабинета. [Инструкция OAuth](docs/OAUTH.md).
- Восстановление пароля по одноразовой ссылке; смена пароля завершает предыдущие сессии.
- Серверный каталог, привязанный к аккаунту. Данные другого пользователя недоступны.
- Добавление, редактирование и удаление товаров и конкурентов через обычные поля.
- Цены с десятичной запятой или точкой; пробелы в суммах допустимы. Границы — целые числа.
- Проверка полей, загрузка, ошибки сети, повторные запросы, пустые состояния.
- Поиск, фильтр по причине, импорт и экспорт JSON.
- Защита от потери изменений между вкладками: устаревшая версия каталога получает `409`.
- Удаление своего аккаунта и данных с подтверждением текущего пароля.
- Адаптивная светлая тема с нейтральной палитрой и графитовыми кнопками.

Ограничения одного каталога: 500 товаров, 100 конкурентов на товар, тело запроса до 1 МБ. Артикул — до 120 символов, название товара/продавца — до 240. Эти ограничения проверяются сервером.

## Режим разработки

```sh
npm install
npm run setup
npm run infra
npm run dev
```

Откройте **http://localhost:5173**. Vite проксирует `/api` и `/reprice` на API в порту 3001. PostgreSQL доступен локально в порту 55432, Mailpit — 8025. Перед этим остановите контейнер приложения, если запускали полный Docker-стек: `docker compose stop app`.

Для отдельных терминалов: `npm run dev:server` и `npm run dev:client`.

`APP_ORIGIN` должен совпадать с адресом открытой страницы. Для Vite это `http://localhost:5173`; для собранного приложения вне Docker задайте `APP_ORIGIN=http://localhost:3001`. В development разрешены оба loopback-имени `localhost` и `127.0.0.1` на том же порту. В production разрешён только точный HTTPS origin. Compose задаёт нужный адрес сам. Если порт 3001 занят, задайте `APP_PORT=3003` перед запуском локального Compose — сайт будет на `http://localhost:3003`.

## Проверки

```sh
npm test
npm run test:integration
npm run build
```

`npm test` запускает расчёт, HTTP-контракт, тесты форм/авторизации в jsdom, проверки конфигурации/паролей и криптографическую проверку OIDC-токенов. Для `npm run test:integration` нужна PostgreSQL: выполните `npm run infra`, либо задайте `TEST_DATABASE_URL`. Интеграционные тесты создают уникальную схему и удаляют только её; рабочие таблицы не очищаются. Письма в этих тестах подменены, реальная отправка не выполняется.

Для сквозной проверки собранного локального Docker-стека: `npm run test:smoke -- --restart`. Скрипт создаёт и удаляет свой тестовый аккаунт, проверяет реальные письма в Mailpit, каталог и сохранение сессии после перезапуска контейнера. При нестандартном порту задайте `SMOKE_URL`, например `http://localhost:3003`; внешние адреса скрипт не принимает.

CI запускает тесты, интеграцию с PostgreSQL и сборку на Node.js 20 и 24. `npm run typecheck` проверяет строгую типизацию отдельно. `npm ci` устанавливает версии из lockfile.

Собранное приложение запускается командой `npm start` после `npm run build`; оно отдаёт и страницу, и API. Конфигурация читается из `.env` и переменных окружения. Миграции выполняются при запуске под блокировкой PostgreSQL.

## Публичное развёртывание

Подготовлены `Dockerfile`, `compose.prod.yaml` и Caddy с автоматическим HTTPS. **Локальный `compose.yaml` предназначен для разработки**, использует тестовую почту и не публикует порты во внешний интерфейс.

На сервере с Docker:

1. Скачайте репозиторий и выполните `npm run setup` (либо заполните `.env` по `.env.example` вручную уникальными секретами).
2. Направьте DNS вашего домена на сервер. Для Caddy должны быть доступны порты 80 и 443.
3. В `.env` укажите `DOMAIN` без протокола, реальный `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`. Для SMTP 465 задайте `SMTP_SECURE=true`; для 587 — `false` (STARTTLS обязателен в production).
4. Запустите:

```sh
docker compose -f compose.prod.yaml up -d --build
```

Адрес сайта: `https://ваш-домен`. База и приложение не открывают порты наружу; доступ идёт через Caddy. Production требует HTTPS, включает Secure cookies и доверяет одному внутреннему прокси. Не выставляйте приложение напрямую в интернет с `TRUST_PROXY=1`.

После настройки проверьте регистрацию, получение письма настоящим почтовым ящиком, вход, сохранение товара, сброс пароля и выход. Доставляемость писем зависит от SMTP-провайдера и конфигурации вашего домена. Mailpit для публичных пользователей не используется.

Обновление:

```sh
npm run backup -- --production
git pull
docker compose -f compose.prod.yaml up -d --build
```

Подробности эксплуатации, резервного копирования и текущие ограничения — в [DEPLOYMENT.md](DEPLOYMENT.md).

## Google и Apple

Кнопки включаются только после заполнения ключей в `.env`. Нужны собственные OAuth-клиенты Google и Apple; ключи не входят в репозиторий. Для Apple требуется публичный HTTPS-домен. Точные callback URL, настройка ключа `.p8` и проверки описаны в [docs/OAUTH.md](docs/OAUTH.md). При совпадении почты аккаунты не объединяются автоматически: сначала войдите в существующий аккаунт, затем подключите провайдера в «Аккаунт и данные».

## API

Исходный контракт задания сохранён: **`POST /reprice`** принимает `Product[]` и возвращает `PriceResult[]` в том же порядке. Он не хранит данные, не раскрывает каталоги и доступен без аккаунта. Лимит запросов включён в запущенном SaaS-приложении.

```sh
curl http://localhost:3001/reprice -H 'Content-Type: application/json' --data-binary @data/products.json
```

PowerShell:

```powershell
curl.exe http://localhost:3001/reprice -H "Content-Type: application/json" --data-binary "@data/products.json"
```

Основные маршруты личного кабинета:

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/auth/session` | Пользователь, доступные провайдеры и CSRF-токен |
| `POST /api/auth/oauth/:provider/start` | Начать вход/привязку Google или Apple |
| `POST /api/auth/register` | Создание аккаунта, письмо подтверждения |
| `POST /api/auth/verify` | Подтверждение одноразовым токеном |
| `POST /api/auth/request-verify` | Повторное письмо подтверждения |
| `POST /api/auth/login` | Вход и новая сессия |
| `POST /api/auth/logout` | Выход |
| `POST /api/auth/request-reset` | Запрос восстановления пароля |
| `POST /api/auth/reset` | Новый пароль по одноразовому токену |
| `GET /api/products` | `{ products, version }` текущего пользователя |
| `PUT /api/products` | Сохранение `{ products, version }` с проверкой версии |
| `DELETE /api/account` | Удаление своего аккаунта, тело `{ password }` |
| `GET /healthz` | Процесс работает |
| `GET /readyz` | Приложение подключено к БД |

Для изменяющих запросов `/api` клиент передаёт cookie и `X-CSRF-Token`, полученный из `/api/auth/session`. После входа токен меняется. OAuth callback использует одноразовый state и перенаправление; его обработка описана в docs/OAUTH.md. Ошибки обычного JSON API — JSON с полем `error`; `401` означает отсутствие входа, `403` — ошибку CSRF/неподтверждённую почту, `409` — конфликт версии, `413` — слишком большой запрос, `429` — превышение лимита.

## Расчёт цены

Именованный экспорт **`calculatePrice(product)` в `src/pricing.ts`** не менялся. Функция чистая, без I/O, валидации и мутаций:

1. Находит минимальную цену конкурента с `inStock: true`.
2. Если таких конкурентов нет: `maxPrice`, `NO_COMPETITORS`.
3. Вычисляет `candidate = Math.floor(best - step)`.
4. Строго ниже минимума: `minPrice`, `AT_MIN`; строго выше максимума: `maxPrice`, `AT_MAX`.
5. Иначе: `candidate`, `UNDERCUT`. Равенство границам включено.

`myPrice` только возвращается как `oldPrice`. Сложность — O(n) времени и O(1) дополнительной памяти. `data/products.json` и `data/expected.json` созданы по числовым примерам задания; это демонстрационные товары.

## Структура

```text
src/                 Типы, чистый расчёт и общая проверка Product
server/app.ts        Express, /reprice, middleware, health checks
server/saas.ts       Авторизация, сессии и каталог
server/oauth.ts      Google/Apple, проверка OIDC и привязка аккаунтов
server/db.ts         PostgreSQL и версионированные миграции
server/passwords.ts  Хеширование паролей
server/mail.ts       SMTP-письма
server/config.ts     Проверка окружения
client/src/Root.tsx  Загрузка сессии и переход в личный кабинет
client/src/Auth.tsx  Формы регистрации, входа и восстановления
client/src/App.tsx   Каталог и результаты расчёта
client/src/ProductForm.tsx  Форма товара и конкурентов
tests/              Unit, API, UI и PostgreSQL-интеграция
scripts/            Создание окружения и резервная копия
```

Секреты, зависимости, сборки и резервные копии исключены из Git. Код создавался с помощью AI; перед интервью стоит самостоятельно разобрать расчёт, HTTP-контракт и проверки доступа.

## Публикация исходников

Создайте пустой публичный репозиторий в своём GitHub, затем из этой папки:

```sh
git remote add origin https://github.com/YOUR_USERNAME/salescout.git
git push -u origin main
```

В GitHub публикуется именно этот проект: его корень должен содержать `src/pricing.ts`. Публикация исходников сама по себе не запускает сайт — для публичного адреса нужен сервер, домен и SMTP.
