# API SaleScout

[← README](../README.md)

Локальный сервер: `http://localhost:3001`. В режиме разработки страница Vite проксирует эти же пути через `http://localhost:5173`. Для JSON-запросов передавайте `Content-Type: application/json`.

## Расчёт цены

`POST /reprice` принимает массив товаров и возвращает массив результатов в том же порядке. Авторизация не требуется. Запрос не читает и не изменяет сохранённые каталоги.

```json
[
  {
    "sku": "IPHONE-15-128",
    "name": "Apple iPhone 15",
    "myPrice": 399990,
    "minPrice": 370000,
    "maxPrice": 420000,
    "step": 10,
    "competitors": [
      { "seller": "Tech Store", "price": 384990, "inStock": true }
    ]
  }
]
```

Ответ `200`:

```json
[
  {
    "sku": "IPHONE-15-128",
    "oldPrice": 399990,
    "newPrice": 384980,
    "reason": "UNDERCUT"
  }
]
```

Пример из файлов репозитория, Bash:

```sh
curl http://localhost:3001/reprice \
  -H 'Content-Type: application/json' \
  --data-binary @data/products.json
```

PowerShell:

```powershell
curl.exe http://localhost:3001/reprice -H "Content-Type: application/json" --data-binary "@data/products.json"
```

Тело, которое не является массивом, или товар с некорректными полями получает `400`. Пустой массив допустим и возвращает `[]`. Числа должны быть конечными и неотрицательными; границы — целыми, `minPrice <= maxPrice`. Дробный шаг допустим. Определения типов: [src/types.ts](../src/types.ts); алгоритм: [src/pricing.ts](../src/pricing.ts).

## Сессия и CSRF

Перед работой с кабинетом вызовите `GET /api/auth/session`. Ответ содержит `user` или `null`, `csrfToken` и доступность провайдеров в `providers`.

Клиент сохраняет cookie и передаёт `X-CSRF-Token` в изменяющих запросах `/api`. После входа сервер регенерирует сессию и возвращает новый токен. При наличии заголовка `Origin` он должен соответствовать адресу приложения. Cookie — HttpOnly и SameSite=Lax; в production также Secure и с префиксом `__Host-`.

## Аккаунты

| Метод и путь | Тело / назначение |
| --- | --- |
| `GET /api/auth/session` | Текущий пользователь, CSRF и доступные провайдеры |
| `POST /api/auth/register` | `{ "name", "email", "password" }`; отправка подтверждения, ответ `202` |
| `POST /api/auth/verify` | `{ "token" }`; подтверждение почты |
| `POST /api/auth/request-verify` | `{ "email" }`; повторная ссылка |
| `POST /api/auth/login` | `{ "email", "password" }`; пользователь и новый CSRF |
| `POST /api/auth/logout` | Выход, ответ `204` |
| `POST /api/auth/request-reset` | `{ "email" }`; письмо восстановления |
| `POST /api/auth/reset` | `{ "token", "password" }`; новый пароль и отзыв старых сессий |
| `POST /api/auth/oauth/:provider/start` | Начать вход или привязку, ответ `{ "url" }`; `provider` — `google` / `apple` |
| `DELETE /api/account` | `{ "password" }`; удалить свой аккаунт и каталог, ответ `204` |

Запись `{ "email", "password" }` в таблице обозначает имена полей объекта, а не готовый JSON. Пароль при создании/сбросе — от 10 до 128 символов, имя — до 80. Письма повторно отправляются не чаще одного раза в минуту для одного адреса и действия. Ссылки подтверждения действуют 24 часа, восстановления — 30 минут.

OAuth callback использует одноразовый state и проверку исходной браузерной сессии. Обратный POST Apple не требует заголовка CSRF: он только сохраняет код до последующего проверенного GET. Обычным клиентам не нужно самостоятельно вызывать callback. [Подробности OAuth](OAUTH.md).

## Каталог

`GET /api/products` требует входа и возвращает:

```json
{ "products": [], "version": 0 }
```

`PUT /api/products` заменяет весь каталог текущего пользователя. Передайте `products` и последнюю полученную `version`:

```json
{ "products": [], "version": 0 }
```

При успехе сервер возвращает сохранённый каталог и увеличенную версию. Если другая вкладка уже изменила каталог, ответ — `409 CONFLICT`. Повторно загрузите каталог и согласуйте изменения. Идентификатор владельца определяется сессией; переданный клиентом `userId` не меняет владельца.

Лимиты: 500 товаров, 100 конкурентов на товар, SKU до 120 символов, название/продавец до 240, числовые значения не выше `Number.MAX_SAFE_INTEGER`. Весь JSON-запрос должен помещаться в 1 МБ.

## Ошибки и состояние сервиса

Ошибки JSON API содержат `error` с сообщением; некоторые также имеют `code` для клиента. Внутренние ошибки содержат `requestId`, связанный с серверным логом.

| Статус | Значение |
| --- | --- |
| `400` | Некорректный JSON, поля или истёкший/использованный почтовый токен |
| `401` | Нет действующей сессии или неверные данные входа |
| `403` | Ошибка CSRF/Origin или неподтверждённая почта |
| `409` | Устаревшая версия каталога |
| `413` | Слишком большой запрос |
| `429` | Превышен лимит запросов |
| `503` | Провайдер входа не настроен или БД недоступна при readiness-проверке |

`GET /healthz` возвращает `{ "status": "ok" }`, если процесс отвечает. `GET /readyz` проверяет соединение с PostgreSQL и возвращает `{ "status": "ready" }` либо `503`. Приватные API имеют `Cache-Control: no-store`.
