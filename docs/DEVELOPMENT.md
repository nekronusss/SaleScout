# Разработка и решение проблем

[← README](../README.md) · [API](API.md) · [OAuth](OAUTH.md) · [Эксплуатация](../DEPLOYMENT.md)

## Два способа запуска

| | Полный Docker-стек | Разработка с Vite |
| --- | --- | --- |
| Запуск | `docker compose up -d --build` | `npm run infra`, затем `npm run dev` |
| Адрес страницы | `http://localhost:3001` | `http://localhost:5173` |
| Где работает API | Контейнер `app` | Локальный процесс `tsx watch`, порт 3001 |
| Где работает база | Контейнер `db` | Тот же контейнер `db` |
| Письма | Mailpit на `http://localhost:8025` | Тот же Mailpit |
| Применение изменений кода | Пересобрать `app` | Vite / tsx обновляют приложение автоматически |
| `APP_ORIGIN` | Compose задаёт автоматически | `http://localhost:5173` в `.env` |

Не запускайте оба API на одном порту. Для перехода от Docker к разработке:

```sh
docker compose stop app
npm run infra
npm run dev
```

Для обратного перехода остановите `npm run dev` через Ctrl+C и запустите `docker compose up -d --build app`. PostgreSQL и каталог сохранятся.

## Проверки изменений

Для обычного изменения кода:

```sh
npm test
npm run build
```

Если затронуты аккаунты, сессии, каталог, OAuth или SQL:

```sh
npm run infra
npm run test:integration
```

Интеграционные тесты используют `TEST_DATABASE_URL`, а при его отсутствии — `DATABASE_URL` из `.env`. Они создают уникальную схему, выполняют миграции и в конце удаляют эту схему. Пользователю БД нужно право создавать схемы. Для CI предусмотрен отдельный PostgreSQL service.

Для проверки собранного приложения и настоящих локальных писем:

```sh
docker compose up -d --build
npm run test:smoke -- --restart
```

Smoke-проверка создаёт собственный аккаунт, подтверждает почту через Mailpit, сохраняет товары, сравнивает расчёт с `data/expected.json`, перезапускает контейнер приложения и проверяет сохранение сессии. Затем проверяет восстановление пароля, отзыв старой сессии и удаляет тестовый аккаунт. Она принимает только локальные HTTP-адреса. Без `--restart` контейнер не перезапускается.

## Если порт 3001 занят

Для полного Docker-стека можно выбрать, например, 3003. На Windows, PowerShell:

```powershell
$env:APP_PORT = "3003"
docker compose up -d --build app
```

На macOS/Linux, Bash:

```sh
export APP_PORT=3003
docker compose up -d --build app
```

Откройте `http://localhost:3003`. Внутренний порт контейнера останется 3001, а адрес почтовых ссылок Compose подставит сам. Переменная действует в текущем терминале; для следующих запусков можно добавить `APP_PORT=3003` в локальный `.env`.

Для smoke-проверки на том же порту:

```powershell
# PowerShell
$env:SMOKE_URL = "http://localhost:3003"
npm run test:smoke -- --restart
```

```sh
# Bash
SMOKE_URL=http://localhost:3003 npm run test:smoke -- --restart
```

`APP_PORT` меняет порт только контейнера приложения. Если заняты 55432, 1025 или 8025, проверьте другие локальные PostgreSQL/Mailpit и портовые привязки `compose.yaml`. При изменении порта PostgreSQL обновите `DATABASE_URL` для локального API; при изменении SMTP-порта — `SMTP_PORT`. Для smoke-проверки с другим веб-портом Mailpit задайте `MAILPIT_URL`.

## Частые вопросы

### Docker сообщает, что daemon недоступен

Запустите Docker Desktop и дождитесь готовности движка. Проверьте `docker version` и `docker compose version`, затем повторите запуск. На Windows нужен режим Linux containers.

### PowerShell запрещает запуск npm.ps1

Используйте `npm.cmd` вместо `npm`, например `npm.cmd install` и `npm.cmd run dev`. Это запускает установленный npm через его Windows-команду.

### В браузере ошибка подключения

Для Docker выполните `docker compose ps` и `docker compose logs --tail=100 app db`. После готовности базы `http://localhost:3001/readyz` должен вернуть `{"status":"ready"}`. Если задали `APP_PORT`, используйте этот порт.

При разработке терминал с `npm run dev` должен оставаться запущенным. Открывайте Vite на 5173. Изменения `.env` применяйте перезапуском процесса; файл окружения не является исходным кодом React.

### Письмо регистрации не пришло

В локальном окружении откройте `http://localhost:8025`: письма попадают в Mailpit. Проверять настоящий почтовый ящик не нужно. Повторная отправка одного вида письма одному аккаунту ограничена одной попыткой в минуту. Если письмо старое, запросите новое и используйте последнюю ссылку.

Для публичного сайта требуется реальный SMTP — настройка описана в [DEPLOYMENT.md](../DEPLOYMENT.md).

### После регистрации не получается войти

Сначала подтвердите почту: откройте ссылку из письма и нажмите кнопку подтверждения. Минимальная длина нового пароля — 10 символов. При потере пароля используйте «Забыли пароль?». Если достигнут лимит запросов (`429`), дождитесь завершения окна ограничения; для авторизации оно составляет 15 минут.

### «Сессия устарела» или ошибка CSRF

Обновите страницу, чтобы получить актуальную сессию и CSRF-токен. Проверьте `APP_ORIGIN`: адрес должен совпадать с открытой страницей. Для Vite — `http://localhost:5173`, для собранного локального сервера — `http://localhost:3001`. В production требуется точный HTTPS origin.

Cookie привязана к имени хоста. Используйте `localhost` последовательно, особенно при OAuth с callback на `localhost`.

### Google и Apple недоступны

Это ожидаемо без собственных ключей. Вход по почте работает независимо от них. Заполните все переменные выбранного провайдера по [инструкции](OAUTH.md) и перезапустите сервер. Apple нельзя проверить на обычном localhost: требуется зарегистрированный HTTPS-домен.

### Каталог изменился в другой вкладке (`409`)

Сервер отклонил сохранение устаревшей версии. Сохраните нужные правки отдельно, закройте форму и нажмите «Обновить список». Затем внесите изменения в актуальный каталог. Повторять старый запрос с той же версией бесполезно.

### После изменения товара исчезла новая цена

Результат расчёта относится к предыдущим данным. После сохранения изменений нажмите «Рассчитать цены». Каталог хранится в базе; результаты можно получить повторным расчётом.

### База перестала принимать пароль после изменения .env

`POSTGRES_PASSWORD` применяется к PostgreSQL при первой инициализации тома. Изменение `.env` не меняет пароль уже созданного пользователя БД. Верните корректные параметры подключения или измените пароль через администратора БД. Перед работой с существующими данными сделайте резервную копию; пересоздание тома удалит каталог и аккаунты.

## Изменения в проекте

Сохраняйте именованный экспорт `calculatePrice` и путь `src/pricing.ts`: это контракт исходного тестового задания. Не связывайте чистый расчёт с БД, HTTP или React. Новые изменения схемы добавляйте отдельной версией миграции в `server/db.ts`.

Не коммитьте `.env`, ключи провайдеров, дампы БД и пользовательские данные. При изменении порта, npm-команды или обязательной настройки обновляйте README вместе с кодом. Для проблемы в API приложите шаги воспроизведения, статус ответа и `requestId`, если он есть; пароли, cookies и токены в issue не нужны.
